    歡迎來到程式的世界 👋

    不需要任何基礎。只要你會用滑鼠、會打字，就可以開始。

    程式是什麼？

    程式 = 寫給電腦的「一步一步的指令」，就像食譜：

    🍳 煎蛋食譜：① 熱鍋 → ② 倒油 → ③ 打蛋 → ④ 煎 2 分鐘 → ⑤ 起鍋
    💻 程式：電腦從 main 開始、由上往下，一個步驟一個步驟照著做。
    ⚠ 電腦很聽話，但也很「死板」 少一個符號、拼錯一個字，它就會直接說「看不懂」。所以你會常常看到紅色的錯誤訊息——這完全正常，每個工程師每天都在遇到！

    在 Dev-C++ 寫出你的第一個程式 🖥️

    這個網頁的「▶ 執行」只是練習用。真正寫程式時，你要在自己的電腦、用學校的 Dev-C++ 完成整個流程。

    為什麼程式要「編譯」？

    你寫的程式叫原始碼（source code），檔案副檔名是 .cpp，是給「人」看的。電腦卻只看得懂 0 和 1。
    所以中間需要一位翻譯官 —— 編譯器（compiler），把原始碼翻成電腦能執行的執行檔（.exe）。
    Dev-C++ 是一個 IDE（整合開發環境）：它把「編輯器（打字）＋編譯器（翻譯）＋執行」包在同一個軟體裡。

    🔬 流程模擬：改了程式，要做什麼才會看到新結果？

    Dev-C++ 操作步驟（對照表）

    要做什麼怎麼做
    新增程式檔檔案(F) → 開新檔案(N) → 原始碼(S)（快速鍵 Ctrl+N）
    存檔Ctrl+S。第一次會跳出 Save As 視窗，檔名預設是 新文件1.cpp，請改成有意義的名字，副檔名保持 .cpp
    只編譯執行(Z) → 編譯(C)（F9）：翻譯，檢查有沒有錯
    只執行執行(Z) → 執行(R)（F10）：跑已經編譯好的檔案
    編譯並執行執行(Z) → 編譯並執行(O)（F11）：一次完成，最常用
    全部重新建置執行(Z) → 全部重新建置(V)（F12）：把整個程式從頭重翻一遍，遇到怪問題時用

    工具列上也有對應的按鈕：由左而右是「編譯、執行、編譯並執行、全部重新建置」。

    讀懂「真正」的錯誤訊息

    網頁上的錯誤訊息是中文的，但 Dev-C++ 的編譯器訊息是英文。編譯失敗時，視窗下方會自動切到「編譯器訊息」分頁，用表格列出：行數、列數、檔案、訊息（訊息開頭有 [Error]）。出錯的那一行程式會被塗成深紅色。雙擊錯誤列，游標會跳到出錯位置。上面的互動模擬裡就可以體驗。

    下面的訊息，都是用這間學校使用的 Dev-C++ 5.11（g++ 4.9.2）實際編譯出來的。

    Dev-C++ 顯示的訊息常見原因
    [Error] expected ';' before 'return'少了分號。注意：它指的是 return 這一行，但真正漏掉分號的是上一行行尾
    [Error] 'total' was not declared in this scope變數 total 沒宣告，或名字打錯
    [Error] 'cout' was not declared in this scope漏了 using namespace std;
    [Fatal Error] iostrem: No such file or directory標頭檔名稱拼錯（Fatal 表示直接停止編譯）
    [Error] expected '}' at end of input大括號 { } 數量不成對
    [Error] stray '\357' in program（後面的數字可能不同）程式裡混進了全形符號（例如 ； ）或看不見的奇怪字元
    [Error] 'include' does not name a type#include 前面漏了 #
    [Error] invalid conversion from 'const char*' to 'char' [-fpermissive]把雙引號的文字 "A" 放進 char（char 要用單引號 'A'）
    [Error] 'sqrt' was not declared in this scope用了 sqrt 卻沒 #include <cmath>
    🛠 處理錯誤的順序 從第一個錯誤開始修，修完就重新編譯。後面的錯誤常常是「連鎖反應」，第一個修好後會一起消失。
    Dev-C++ 顯示 expected ';' before 'return'，指向第 8 行（return 0;）。你應該先檢查？
    1. 第 8 行的 return 拼錯了
    2. 整個程式重寫
    3. 第 8 行上面一行的結尾，是不是少了 ;
    編譯器是讀到 return 才發現「前面好像漏了分號」，所以報告的行號常常是「錯誤的下一行」。
    'sum' was not declared in this scope 是什麼意思？
    1. sum 的值太大
    2. sum 還沒宣告（或名字打錯）
    3. sum 不能當變數名稱
    「not declared」＝沒有宣告。回頭檢查有沒有 int sum;，以及大小寫、拼字。
    ⚠ 網頁練習器 ≠ 真正的編譯器
    • 練習器的錯誤訊息是中文；Dev-C++ 是英文，而且比較「冷淡」，不會建議你怎麼改。
    • 沒有給初始值的變數，練習器會當成 0；在真正的電腦上，它的值是不確定的，不能依賴。
    • 真正的編譯器有些問題完全不提醒：例如 if(x=3)、整數除法被捨去小數，Dev-C++ 都編譯過關、沒有任何警告，要靠你自己小心。
    • 有時候「沒借工具箱」在 Dev-C++ 剛好也能過（例如沒寫 <algorithm> 就用 max），但換一台電腦或別的編譯器就可能失敗。所以一律需要什麼就借什麼。

    第 3 課 · 0907

    變數：會記東西的盒子 📦

    電腦要計算，就得先把數字「記」起來。變數就是用來記數字的盒子。

    什麼是變數？

    變數像是貼著名字標籤的盒子：盒子有名字（例如 x）、有種類（只能放某種東西）、裡面放著數值。
    x
    10
    y
    40
    int x=10, y=40; 的意思：做出兩個放整數的盒子，名字叫 x 和 y，分別放進 10 和 40。

    資料型態：盒子的種類

    型態放什麼例子
    int整數（沒有小數點）10、-3、0
    float小數（浮點數）3.14、-0.5
    char一個字元'A'、'7'（用單引號）
    📝 取名字的規則 只能用英文字母、數字、底線 _；不能用數字開頭；不能和 int、return 這類保留字相同；大小寫視為不同（Sum ≠ sum）。

    先記住這句：= 是「放進去」

    c = a + b; 的讀法：先算右邊，再把結果放進左邊的盒子。（第 6 課會再深入）

    宣告 vs. 給初始值

    寫法發生什麼事
    int a;只做出盒子，裡面是空的（不是 0！內容不確定）
    int b=5;做出盒子，並放進初始值 5
    int a; a=5;先做盒子，之後再放值（值還沒放進去之前，不要去讀它）
    ⚠ 習慣：沒有把握，就給初始值 需要累加的變數（例如 sum）一定要先寫成 int sum=0;。練習器會用橘色警告提醒你，並暫時當成 0；但在真正的電腦上，沒給值的變數內容是不確定的。
    int sum; sum = sum + 5; 之後，sum 是多少？
    1. 5
    2. 0
    3. 不確定，因為一開始 sum 沒有值
    「舊的 sum + 5」中的舊 sum 是不確定的內容。要累加，先寫 int sum=0;。

    實際操作：算平均

    按 👣 逐步看變數，看盒子裡的數字怎麼一步步改變。

    ⚠ 有雙引號 vs. 沒有雙引號 cout<<"avg"; 印出的是 avg 這三個字；cout<<avg; 印出的是盒子 avg 裡面的數值。
    要印出變數的結果，就不能加雙引號。試著在上面的程式把 avg 加上雙引號看看。
    哪一個是不合法的變數名稱？
    1. 2score

    3. my_score

    2score 以數字開頭，不行！score2 數字在後面就可以。

    cin 輸入：讓使用者決定數字

    有了輸入，同一個程式就能算出不同人的答案。

    cout 是「輸出」，cin 是「輸入」

    下面程式裡 n 本來是 3，但 cin>>n 會用你輸入的值取代它。

    算三科的總分和平均

    咦？259 ÷ 3 應該是 86.333…，為什麼電腦印出 86？

    🧠 整數 ÷ 整數 = 整數

    在 C++ 裡，兩個整數相除，結果也是整數，小數部分會被直接丟掉（無條件捨去）：
    259 / 3 → 86　　7 / 2 → 3　　1 / 2 → 0　　-7 / 2 → -3（往 0 的方向捨去）
    只要其中一邊是小數，就會算出小數：259 / 3.0 → 86.3333

    2. 3
    3. 3.0

    第 5 課

    字元與字串：文字也是資料 🔤

    姓名、班級、等第「A」…… 程式不只處理數字，也要處理文字。

    7、'7'、"7" 是三種不同的東西！

    寫法型態意思
    7int數字 7，可以計算
    '7'char「一個」字元（單引號），電腦用編號（ASCII 碼）儲存
    "7"、"Amy"string「一串」文字（雙引號）。要借 <string>（Dev-C++ 通常借了 iostream 也能用，但建議明確寫）
    📌 記憶口訣單引號放一個字元；雙引號放一串文字。中文字請一律用 string。
    🔎 發現'A'+1 得到 66，因為字元是用編號儲存的（'A' 的編號是 65）。想把結果再變回字元，要用 (char) 轉型。
    想存放學生姓名 "Amy"，宣告哪個正確？
    1. char name = "Amy";
    2. string name = "Amy";
    3. int name = "Amy";
    4. string name = 'Amy';
    一串文字用 string 加雙引號。char 只能放一個字元；單引號裡也只能放一個字元。

    🐞 修修看

    用 cin 輸入文字：遇到「空白」就停

    cin >> 每次讀一個「以空白隔開」的資料。所以輸入 Amy Chen 15 時，name 只拿到 Amy，接下來 age 會去讀 Chen ——但那不是數字，讀取就失敗了。

    進階：想讀「含空白的一整行」怎麼辦？

    可以用 getline(cin, name);，它會讀到按下 Enter 為止。但如果前面剛用過 cin >>，Enter 的換行會被留在輸入中，要先處理掉，這在之後的課程會學到。網頁練習器目前不支援 getline。

    第 6 課 · 0914

    = 不是「等於」，是「放進去」

    這是初學者最容易搞混、也最重要的觀念。

    數學：x = x + 1 是一個不可能成立的等式。
    C++：x = x + 1 是一個動作：先算右邊，再把結果放進左邊的盒子。
    所以 sum = sum + i 的意思是：新的 sum = 舊的 sum + i。

    逐步執行看看：sum 從 18 變成幾？

    🤔 這題你能預測嗎？

    int x = 1, y = 0;
x = y;
y = x;
cout<<y;
    最後印出的 y 是多少？
    1. 1
    2. 0
    3. 0 和 1 對調，所以是 1
    第 2 行 x=y：x 被改成 0（原來的 1 消失了）。第 3 行 y=x：把 0 放進 y，還是 0。
    想要「對調」兩個變數，需要更多技巧 → 下一課！
    int a=5; a=a+2; a=a*2; 之後，a 是？
    1. 7
    2. 10
    3. 14
    4. 12
    5 → 先 +2 變 7 → 再 ×2 變 14。每一行都用「前一行的結果」。

    和數學一樣：括號 → 乘 / 除 / 取餘（同級，由左到右）→ 加 / 減。

    2. 1
    3. 0
    4. 3.33

    第 9 課

    標頭檔 #include：向「工具箱」借工具 🧰

    每個程式最前面都有 #include <iostream>，它到底是什麼？不寫會怎樣？

    為什麼需要標頭檔？

    C++ 語言本身只有「最基本」的功能。像印字（cout）、開根號（sqrt）、找最大值（max）這些常用功能，被分類收進不同的「工具箱」，這些工具箱就叫標頭檔（header file）。
    要用哪個工具，就用 #include 把那個工具箱「借進來」。不借，電腦就找不到工具。
    📌 寫法規則 ① 一定要有 #　② 標頭檔名稱放在 < > 尖括號裡　③ 結尾不加分號　④ 寫在整個程式的最前面（在 main 之前）。
    名稱不用 .h：C++ 寫 <cmath>（C 語言舊寫法是 <math.h>）。

    常用標頭檔一覽

    標頭檔提供的工具例子
    <iostream>輸入輸出cout、cin、endl
    <cmath>數學函式sqrt(x) 開根號、pow(a,b) a 的 b 次方、abs(x) 絕對值、floor/ceil/round
    <algorithm>演算法工具max(a,b)、min(a,b)（第 14 課會用到）
    <iomanip>控制輸出格式setprecision(n) 控制小數位數
    <string>文字處理string 型態
    🧪 在 Dev-C++ 5.11 實測 沒借 <cmath> 就用 sqrt → 會錯；沒借 <iomanip> 就用 setprecision → 會錯；但沒借 <algorithm> 就用 max → 竟然能過（因為別的標頭檔偷偷幫你借了）。這種「碰巧能過」不可靠，請養成用到什麼就借什麼的習慣。
    ⚠ 還有一個「萬用工具箱」 #include <bits/stdc++.h> 會一次借進幾乎所有工具箱，比賽時很常見。但它不是標準寫法、有些電腦編譯不過，也讓你不知道自己到底用了什麼。學習階段請需要什麼就借什麼。
    進階：尖括號 < > 和雙引號 " " 有什麼不同？

    #include <名稱>：到「系統提供」的地方找。#include "名稱.h"：先到「你自己的資料夾」找 —— 以後你會自己寫標頭檔來整理大型程式。

    ① 親手借借看

    🔎 觀察刪掉 #include <cmath> 之後，錯誤訊息說了什麼？它會告訴你該借哪個標頭檔！記住這種提示，以後遇到「xxx 找不到」時先想：是不是少借了工具箱？
    想用 max(a,b) 找兩數中較大的，應該加上哪個標頭檔？
    1. #include <iostream>
    2. #include <algorithm>
    3. #include <string>
    max 和 min 收在 <algorithm>。
    下面哪一行寫法正確？
    1. include <cmath>
    2. #include <cmath>;
    3. #include <cmath>
    4. #include cmath
    要有 #、要有尖括號、結尾不加分號。

    提示

    第一個錯誤：iostream 的拼字。第二個錯誤：用了 sqrt，卻沒借 cmath。

    直角三角形兩股 a、b，斜邊 c = √(a² + b²)。需要的工具：sqrt（pow(a,2) 也可以用，或直接 a*a）。

    🔬 80 分到 89 分之間？

    把 s 改成 95 再執行：第一行還是 1（成立），顯然錯了！

    (5>3) && (2>4) 的結果是？
    1. 1（成立）
    2. 0（不成立）
    && 是「而且」，兩邊都要成立才成立。5>3 成立，但 2>4 不成立，所以整體不成立 = 0。

    要「而且」→ &&。用 ||（或者）的話，任何數字都會成立。

    除錯：像偵探一樣抓 bug 🕵️

    種類什麼時候發現例子怎麼找
    編譯錯誤程式跑不起來，編譯器擋下來少分號、變數沒宣告看錯誤訊息的行號，從第一個開始修
    執行錯誤跑到一半當掉整數除以 0看是哪一步出事，檢查輸入資料
    邏輯錯誤程式跑得動，但答案不對算平均得 86 不是 86.3最難！要靠追蹤和測資

    2. 執行錯誤
    3. 邏輯錯誤

    四個步驟找 bug

    ① 讀：有紅字？先讀訊息和行號。
    ② 猜：不執行，先在紙上預測結果，再和實際比較，差異就是線索。
    ③ 追：用 👣 逐步執行（Dev-C++ 裡可以多印幾個變數出來看），看哪一步的數字開始不對。
    ④ 改：一次只改一個地方，改完馬上重新測試。

    練習：預測 → 追蹤 → 修正

    這個程式要算 4 和 6 的平均，應該是 5，但執行後是 7。先預測為什麼，再用 👣 追蹤驗證。

    好的測資：專挑「邊界」測

    很多 bug 藏在剛好等於界線的地方。例如「60 分以上及格」，你只測 80 分和 30 分，是找不到 > 和 >= 差別的。測資要包含：界線本身、界線的前一個和後一個、極端值（0、100、負數）、相等的情況。

    🧠 小結「跑得動」不等於「正確」。每寫完一個判斷式，都要想：界線值會怎樣？
